# 知识模块编写模板

供维护者扩展使用，不是 UI 任务的运行时清单。编写真正模块时替换这里的说明性示例。

## 模块契约

- 稳定模块 ID 与小写连字符文件名：
- 触发场景；不适用情况：
- 原稿或一手来源、章节、核对日期、证据局限：
- 与已有规则的重叠及冲突处理：
- 对应中英文文件与相同规则 ID：

## 规则格式

每条规则用稳定标题，例如 `## FORM-01 · 失败后保留输入`，并声明 **Contract（契约）**、**Default（默认）** 或 **Optional（可选）**。在两份清单中使用相同 ID 与等级。默认建议要有判断条件和合理替代方案；可选效果要说明收益；契约要求要有具体行为/数据/无障碍后果，不能只代表审美偏好。

每条规则应包含：

1. 适用条件与用户问题。
2. 判断依据、可实施行为、例外/回退。
3. 可观察验收，适用时含反例或失败路径。
4. 非显然主张的来源与证据局限。

## 注册与验证

在两个 `manifest.json` 中加入模块路径、规则 ID 和等级，在两个 `SKILL.md` 路由表加入场景入口；补充来源和行为案例。包内链接不越出各自语言目录。结构与双语对齐校验后，用真实任务评估，不把预期答案喂给评估 agent。退役 ID 不改号、不复用，替代关系应记录。
