# Ludi UI

把 UI 需求转成可运行、可验证的改动，尊重产品、技术栈和设计系统。本技能与框架无关，使用宿主已有的文件、终端、浏览器和测试工具；不要求特定 MCP、CLI、联网能力或其他 skill。

## 从用户要求的结果开始

明确目标路由/组件、用户任务，以及本次属于**新建**、**修改**还是**审查**。只要求审查时保持只读，除非用户要求修复。局部优化保留现有视觉身份；重设计遵循用户要求的新方向，不暗中扩大为产品重写。

检查项目指令、包脚本、目标代码、相邻组件、设计 token、数据契约和已有测试。有运行条件时观察目标界面。当前代码和实际行为的证据优先于从截图、文件名作出的推断。保留无关的工作区改动。

常规选择从项目证据中解决；缺失信息确实影响产品结果、数据含义或授权范围时才提问，同时继续不依赖答案的工作。缺少设计文档不应阻断小范围修改。新界面按需求建立一致的字体、间距、颜色和组件语言，不自动套用 AI 聊天产品的外观。

## 先明确判断，再实施

1. 说明观察到的问题、预期行为、影响界面和相关规则 ID。新建时明确主要用户任务、视觉方向及必要状态。先处理数据丢失、误操作、不可访问控件和流程阻断，再处理装饰。
2. 明确交互契约：值还是命令；草稿还是已应用状态；加载/空/错/成功；关闭/撤销；键盘与移动端行为。优先使用现有组件库的可访问基础组件，再考虑自建底层设施。
3. 在现有边界内实施。除非需求要求变更，否则保留 API 请求、校验、权限展示、本地化、路由和埋点语义。不要为满足视觉建议而编造数据、权限、撤销接口、持久化草稿或业务能力。
4. 使用项目适用的检查及实际渲染结果验证改动。覆盖适用的失败、键盘、窄屏、长内容、主题和减少动态效果路径。检查规模与改动相称；间距微调不需要运行无关的全量测试或引入新框架。
5. 报告改动、原因和验证方式，给出真实命令、结果与局限。必要能力缺失时标记 `NOT_TESTED`，指出缺失的证据，并完成其他可行检查。

## 按上下文应用规则

- **Contract（契约）**：在适用场景中保护行为、数据或无障碍的要求。**Default（默认）**：起点建议，项目证据支持其他方案时说明理由。**Optional（可选）**：需有明确收益的效果。这些等级是本技能的工程约定，不代表每句话都是 Web 标准。
- 用户需求确定范围与风格，项目约束及功能/无障碍需要限定实现方式。发生冲突时说明具体后果并提出替代方案，不暗中忽略一方。原始笔记的口诀不能覆盖产品事实或已核实的标准。
- 264px、30/60/80%、2.5 秒、20% 收起阈值、字重偏移等均为示例，不是全局常量。按实际内容、视口、设备、延迟、字体与组件库选择 token 和阈值。
- 保留可见焦点、可操作的取消路径，以及临时/悬停界面之外的关键信息。Esc 通常用于关闭弹窗或安全取消，绝不用于确认危险操作。
- 复杂动效、隐藏筛选、图表对比、导出、自动保存、层级选择均为条件能力；只在用户范围和数据契约支持时引入。

## 交付约定

实施任务应交付改动文件及可用流程，不只给建议。审查任务应按优先级给出问题、文件/行号证据、用户后果与具体修复方向，区分实测失败和未验证风险。不得从静态审查或合成事件推导出已经完成浏览器、真实输入法、读屏或生产验证。

维护本技能时，使用[知识模块模板](templates/knowledge-module.md)与 `manifest.json`：保留规则 ID，补齐双语版本，在本路由表注册模块，并校验两个语言包。普通 UI 任务不授权修改技能本身。
