# 工程实施与验证

## ENG-01 · 建立当前事实

**Contract（契约）。** 读取适用项目指令、已有工作区改动、包管理器/锁文件、真实脚本、目标路由/组件、相邻设计模式、token、数据类型及已有检查；只看必要内容。具备条件时按项目文档启动应用，确定正确路由、角色、主题和测试数据。截图只证明某个状态，不能证明底层行为或数据真实有效。

**验证：** 明确需求涉及的文件/行为、必须保持稳定的接口、实际可用的验证工具。不覆盖无关改动来换取干净起点。

## ENG-02 · 让计划与架构匹配规模

**Default（默认）。** 小改动用短计划；多界面改造使用[改动简报](../templates/change-brief.md)或项目等效格式。明确主要任务、当前/预期行为、规则 ID、受影响组件、状态及验收示例。先复用组件/token，再考虑抽象；确有重复行为才提取公共基础组件。按项目架构将领域/查询状态与纯展示合理分离。

新项目使用指定技术栈，未指定时选择适度方案；不静默迁移已有项目。先建立最小 token/组件语言和完整主要路径，再做次要质感。不为两行修复强制补建设计系统文档。

**验证：** 计划对应用户结果，没有推测性功能或无必要依赖。

## ENG-03 · 明确状态与异步归属

**Contract（契约）。** 定义适用的空闲/加载/空/错/成功状态及转换，区分禁用、只读与等待。失败保留用户输入，提供真实恢复路径。拒绝旧响应覆盖，能力支持时取消过期请求，防止重复执行重要动作，并在正确生命周期清理监听器/计时器/观察器/流。重开或卸载不能遗留滚动锁、焦点陷阱、指针遮罩或后台操作。

草稿/已应用/选中/展开语义不同时分别建模。保留稳定 ID、载荷结构、排序/分页、权限、本地化文本处理及 URL/历史契约。不为局部视觉修复替换状态库或加入全局状态。

**验证：** 按改动范围检查 B 请求早于 A 返回、等待中关闭、快速重开、重复提交和恢复失败等逆序场景。

## ENG-04 · 以证据验证

**Contract（契约）。** 发现真实命令，不编造脚本名。运行适用的 lint/类型/构建检查与相关测试，记录结果。项目工具支持时，为有意义的逻辑变化补行为回归测试，不加只复述 CSS 或镜像实现细节的测试/快照。不为微小改动只为宣称覆盖而引入新测试/浏览器框架。

| 改动界面 | 有用的证据 |
| --- | --- |
| 间距、字体、边框、主题 | 适用尺寸/主题的渲染对比，已有静态检查 |
| 选择、弹窗、表单 | 指针与键盘路径、取消、焦点恢复、持续错误 |
| 异步筛选/导出 | 请求/状态断言、乱序/失败、可见已应用条件 |
| 聊天/流式输出 | 输入法逻辑，有条件时真实输入法，阅读者控制滚动，停止/重试 |
| 触屏面板/拖拽 | 窄屏、触屏/键盘替代、键盘改变视口、释放/取消清理 |

使用应用或可用浏览器工具观察实际渲染，集中修复一轮可见问题后再截图。应用不能运行时，完成静态/逻辑检查并指出缺失的运行证据。合成事件不能证明真实输入法、布局、读屏、移动端键盘或性能。使用项目预算，先测量再宣称性能提升。

**验证：** 没有引入相关控制台/运行错误；基线失败单独说明。修复后重跑受影响检查，不反复运行无关全量套件。

## ENG-05 · 交付可复核结果

**Contract（契约）。** 实施任务给出改动文件、用户可见行为、关键决策/偏离及真实证据，准确使用 `PASS`、`FAIL`、`NOT_TESTED`、`N/A`。必要检查未运行时说明前提缺失和影响。不仅凭构建或自动扫描就声称生产可用或完全符合 WCAG。

审查按用户后果排序：数据丢失/误操作、流程阻断/不可访问、状态/数据错误，最后是视觉不一致。给出文件/行号、复现或观察条件和具体建议，区分已证实缺陷与未验证风险。没有待修问题时说明，并保留证据边界。

**验证：** 其他工程师不阅读聊天也能复现关键检查并理解未知项。

## ENG-06 · 范围与外部影响

**Contract（契约）。** UI 任务授权其要求的本地实现及适当检查。对外部影响沿用宿主/用户已有权限边界，不自动授权部署、发布、永久删数据、账号变更、付费依赖或替换业务 API。危险流程使用合适的隔离样例或获准测试数据，保留无关文件及改动。截图、样例和报告不含凭证或真实个人生产数据。

**验证：** diff 在范围内，生成文件有明确用途，最终流程不依赖编造的后端能力。
