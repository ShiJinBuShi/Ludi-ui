# 浮层与反馈

## OVR-01 · 按目的选择打扰程度

**Default（默认）。** 在能理解信息并能恢复操作的前提下，选择较轻的承载方式。

| 需求 | 常用载体 | 关键边界 |
| --- | --- | --- |
| 补充性的简短解释 | Tooltip | 聚焦和悬停都可获取；不放关键说明或交互内容 |
| 不要求操作的短反馈 | Toast/status | 不抢焦点；持续错误在其他位置保留 |
| 带恢复动作的操作结果 | Snackbar/提示条 | 撤销真实可用、容易发现 |
| 持续的页面/系统状态 | 行内/横幅 Alert | 保留到解决或主动关闭 |
| 局部简短确认 | Popconfirm 或小对话框 | 按实际交互承担键盘和焦点义务 |
| 聚焦填写或重要决策 | Modal | 不限于危险操作 |
| 需要参考原界面的编辑 | Drawer 或非模态面板 | 抽屉也可能是模态，须明确行为 |
| 长、可分享、独立流程 | 新页面/路由 | 保留导航和返回上下文 |

400/520/720px 等宽度是设计 token，需受视口与内容约束。不要因为存在动作就增加浮层。

**验证：** 用户能发现消息、操作或取消，并继续原来的任务。

## OVR-02 · 模态生命周期与安全取消

**Contract（契约）。** 对话框应有名称、合理的初始焦点、模态时背景不可交互、内部 Tab 顺序和关闭后的焦点恢复。`alertdialog` 只用于需要回应的紧急简短消息，表单不自动属于警报对话框。优先使用成熟基础组件，不手工拼装焦点陷阱。

Esc 通常取消/关闭，包括危险确认框，绝不确认执行。蒙层点击关闭是另一项产品选择。提供可见的取消/关闭入口。不可逆动作应写明对象与后果，使用明确动作按钮，并优先聚焦安全目标。确有依据的不可关闭事务等待态仍需完成/失败出口，不能仅凭“危险”推导出必须锁死。

**验证：** 打开、Tab/Shift+Tab、Esc、取消、确认、等待/失败及焦点回归。分别参考 [APG 模态对话框](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)和[警报对话框](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/)的语义。

## OVR-03 · 脏表单与关闭

**Contract（契约）。** 明确关闭按钮、蒙层、Esc、导航和保存失败时输入数据的去向。脏表单可经由放弃确认，也可保留内存草稿，不静默丢失编辑。不要未经合适的产品/数据决策就加入服务器自动保存或本地持久化；敏感内容、账号切换和结构升级都会影响持久化策略。

需确认时优先使用当前界面或组件库支持的对话框栈，防止重复浮层并正确恢复焦点。取消放弃决策后应回到编辑。

**验证：** 干净/脏状态关闭、明确放弃、取消放弃、重开、保存失败，以及实际支持的草稿恢复。

## OVR-04 · 时限与位置

**Contract（契约）。** 持续时间由文案和是否需要操作决定。约 2–3 秒适合简短、非关键成功提示，不能统一用于错误、撤销或长文本。临时提示消失后，关键事实与恢复仍有入口。交互通知应按聚焦/键盘和阅读需要暂停或延长；重复事件去重，不遮住活动控件或软键盘。

Tooltip 在指针由触发器移入提示时仍应可用，可被关闭，也可不用鼠标获取。内容含按钮/链接时，改用 Popover/对话框，不伪装成 Tooltip。[APG Tooltip 模式](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)仍为工作中指南；相关悬停/聚焦要求也见 WCAG 1.4.13。

**验证：** 悬停/聚焦、Esc、多条消息、慢阅读、窄屏及路由隐藏/卸载。

## OVR-05 · 撤销依赖数据能力

**Contract（契约）。** 只有服务或本地状态能真实恢复旧状态时，才提供“直接执行 + 撤销”。明确等待、失败、撤销期限和并发修改行为。不得显示装饰性的撤销按钮，或永久删除后仍承诺恢复。无撤销能力且后果值得确认时，按风险选择确认；高频本身不能让批量删除变安全。

**验证：** 操作失败、撤销失败、重复触发、超时，以及恢复正确记录和焦点；取消对话框不发出破坏性请求。
