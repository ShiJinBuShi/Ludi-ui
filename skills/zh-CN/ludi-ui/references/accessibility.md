# 无障碍

只读取与本次交互有关的章节。这里是针对改动的质量底线，不等同于完整 WCAG 符合性审计。

## A11Y-01 · 语义和名称

**Contract（契约）。** 优先使用原生按钮、链接、输入框、选择器和表单标签。动作用按钮，导航用链接；纯图标控件必须有可访问名称，可见标签应与可访问名称一致。没有对应行为时，不添加 menu、combobox 或 dialog 角色。复用组件库已验证的基础组件，检查最终语义，而非只看组件名。

**验证：** 检查改动控件的名称、角色、状态、标签和错误关联。装饰图标不向辅助技术重复播报。

## A11Y-02 · 键盘与焦点

**Contract（契约）。** 主要流程可以不用指针完成。焦点保持可见，不被吸顶区域、面板或通知遮挡。遵循相应控件的键盘模型，不把菜单/列表的每个选项都加入页面 Tab 顺序。快捷键限定在活动界面内，并尊重文字输入与输入法。删除焦点所在项后，把焦点移到仍存在且符合任务逻辑的位置。

**验证：** Tab/Shift+Tab、Enter/Space、适用的方向键、Esc、浮层开关和焦点恢复。不得使用全局 `outline: none`。

## A11Y-03 · 对比度与非颜色线索

**Contract（契约）。** 以 WCAG 2.2 AA 为目标时，按标准及例外检查：普通文本 4.5:1，大文本 3:1，适用的非文本控件/状态指示 3:1。大文本指至少 18pt 常规或 14pt 粗体，不是任意标题。在支持的主题中测量实际合成背景上的颜色。错误、选中、涨跌方向需要文字、形状或图标，不能只靠颜色。装饰性色阶可以很细微，但控件边界和焦点仍需可辨认。

**验证：** 实际背景上的对比度；按准则适用范围检查禁用/悬停/焦点状态；表单与图表的信息不依赖颜色才能理解。

## A11Y-04 · 反馈、错误与时限

**Contract（契约）。** 字段错误持续到内容修正或重新校验，并与对应字段关联。异步状态使用有意义的播报，避免无必要地抢焦点；强打断播报只用于紧急信息。不逐个播报流式 token。关键恢复动作不能只存在于会消失的 Toast。

**验证：** 失败、修正、重试、等待和通知超时行为。自动检查不能证明播报易于理解；需要且具备条件时实测辅助技术。

## A11Y-05 · 重排、点击目标与动态效果

**Contract（契约）。** 使用真实内容检查窄屏和缩放。320 CSS 像素宽度是有用的 WCAG 重排检查条件；二维表格/图形有特定例外，不代表整个页面豁免。WCAG 2.2 AA 的目标尺寸通常为 24×24 CSS 像素，或满足间距/其他例外；合适时采用平台/设计系统更大的触屏目标。尊重减少动态效果设置，为拖拽提供替代操作，不只依赖悬停。

**验证：** 核心拖拽动作可由键盘或可见按钮完成；触屏、缩放、较长译文和减少动态效果下仍能完成相同任务。

## 核对标准

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)：按场景查阅 1.4.3、1.4.10–13、2.1.1–2、2.4.7、2.4.11、2.5.7–8、3.3.1–2、4.1.2–3。
- [ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：按实际控件查相应模式；APG 是实现指南，本身不是 WCAG 符合性标准。
