# 视觉系统与质感

## VIS-01 · 层次清楚、区分充分

**Default（默认）。** 复用语义化 surface/text/border/action/status token 和现有组件系统。新建时按产品与内容确定一致的视觉方向，局部优化时改善层次但保留身份。用间距、对齐、字号层级、底色对比及有选择的边框说明结构和任务优先级。

减少冗余的层层套框，但不全局禁用边框、黑色背景或高对比。媒体预览、高对比主题可能需要它们。原笔记中 1–3% 明度差是风格起点，不能保证无障碍。在项目支持的亮/暗/高对比环境下观察实际内容。

**验证：** 真实显示尺寸下，主操作、分组、控件边界、选中和禁用态仍可区分。

## VIS-02 · 焦点与状态不撑动布局

**Contract（契约）。** 保留明显的键盘焦点。轻微双阴影可辅助表达，但不自动等价于有效焦点指示；保留强制颜色模式支持。预留边框空间或用 outline/内阴影，使焦点和选中不改变控件尺寸。不全局移除 outline，也不因为高像素比就统一把边框减半。

示例需按实测对比度调整 token：

```css
.control { box-sizing: border-box; border: 1px solid transparent; }
.control:focus-visible {
  outline: 2px solid var(--focus-ring);
  outline-offset: 2px;
}
@media (forced-colors: active) {
  .control:focus-visible { outline-color: Highlight; }
}
```

**验证：** 支持主题中的键盘焦点，有条件时检查强制颜色模式，以及 hover/focus/选中前后几何尺寸不变。

## VIS-03 · 字体与稳定数字

**Default（默认）。** 按项目字体和本地化需求建立可读字号、行高、内容宽度与层级。动态数字列/计数器在字体支持时使用 `tabular-nums`，位数增加还需预留空间。行内图标 `-0.125em` 等偏移应按字体做光学校正，不能全局套用。

暗色字重调整是可选项，先看实际渲染。中间字重需要合适的可变字体或实际字形，静态字体设为 360 不保证得到对应外观。不声称固定 10% 视觉效应，不全局统一减 40。`text-wrap: pretty` 可在支持时渐进改善正文，保留普通换行回退。

**验证：** 真实中英文、字体不可用时的回退、长标题、位数变化和双主题。

## VIS-04 · 几何一致与展开折叠

**Default（默认）。** 真正同心且间距均匀的嵌套形状，可从 `内圆角 = max(0, 外圆角 - 间距)` 开始。不是圆角容器内每个子项都适用；内容对齐和现有 token 同样重要。使用少量一致的间距/圆角值，避免大量近似随机值。

内容自适应折叠可用 Grid `0fr`→`1fr` 减少反复 JS 测量，但内层应可收缩：`min-height: 0; overflow: hidden`。CSS 裁切不会自动让控件退出键盘/辅助技术，应同步展开状态、焦点、`hidden`/`inert` 或基础组件等效机制，并覆盖减少动态效果和无动画路径。退出动画延迟移除时，内容应立即不可交互，并可靠完成隐藏。

**验证：** 空/长/动态内容、折叠时内部有焦点、动画中断及布局稳定性。

## VIS-05 · 动效服务于目的

**Default（默认）。** 直接操控应及时跟随指针，松手后可短暂吸附。确认反馈按产品气质使用克制回弹。用命名时长/曲线 token，合适时优先 transform/opacity，避免 `transition: all`。动画不能拖延状态提交或恢复入口。

逐字模糊、大幅缩放、持续运动均为可选且可能昂贵。确有体验收益时优先有界的 chunk 效果。`prefers-reduced-motion: reduce` 时移除/简化非必要动画和平滑滚动，同时保留反馈；组件内定向覆盖，不盲目关闭整个应用所有过渡。

**验证：** 中断/连击、适用时的慢设备或长输出、减少动态效果及卸载清理。[减少动态效果参考](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)解释用户偏好，并不规定统一动画时长。
